# MCP reference

For anyone wiring Editmamei into an MCP client or auditing what it does on a machine. To install it, start with [installation.md](installation.md). For the tool list, see [tools.md](tools.md).

## Connect a client

Editmamei is a local stdio server. In any MCP client, add a server that runs `npx -y editmamei`:

```json
{
  "mcpServers": {
    "editmamei": {
      "command": "npx",
      "args": ["-y", "editmamei"]
    }
  }
}
```

In Claude Code by hand: `claude mcp add --scope user editmamei -- npx -y editmamei`. [clients.md](clients.md) has the config for 17 clients.

## Architecture

```
MCP client ──stdio, JSON-RPC──▶ editmamei (Node.js MCP server)
                                  │
                                  ├─ ps_* tools ──▶ ExtendScript, most of it built by editmamei-core (Go)
                                  │                   ├─ Windows: cscript + VBScript shim → COM DoJavaScript
                                  │                   └─ macOS:   osascript → do javascript
                                  │                          ▼
                                  │                   Adobe Photoshop 2026 (your install)
                                  │
                                  ├─ gimp_* tools ─▶ one warm, headless gimp-console process
                                  │                  (Python-Fu bridge, JSON request/response files)
                                  │                          ▼
                                  │                   GIMP 3.2 (your install)
                                  │
                                  └─ perception ──▶ ONNX models run on-device (onnxruntime-web)
```

- **Photoshop.** A `ps_*` call runs one or more ExtendScript snippets in Photoshop. Most are generated by the bundled `editmamei-core` Go binary; some are still built in TypeScript. Each snippet runs through a short-lived child process: a VBScript shim holding the COM handle on Windows, `osascript` on macOS. Scripts are serialized through one queue, each tool has its own timeout budget, and a wedged Photoshop fails the call instead of hanging the server.
- **GIMP.** `gimp_*` tools talk to a single `gimp-console` started on the first call and kept warm. Requests and responses travel as JSON files; the command line GIMP sees is a fixed constant, so model-supplied values never reach a shell or a Python literal. Adjustments are GEGL filters that stay live in the saved `.xcf`.
- **Perception.** Face, object and scene detection run locally on bundled ONNX models (UltraFace, D-FINE) and return real document coordinates, so the model can target "the person on the left" without a cloud vision call.
- **Editor registration.** By default the `ps_*` tools register, and the `gimp_*` tools join them when GIMP is found at startup. Pin one editor with `EDITMAMEI_EDITOR=photoshop` or `EDITMAMEI_EDITOR=gimp`.

## Design principles

- **Measure, don't eyeball.** A dedicated set of verification tools (histogram, region compare, layer-bounds diff, selection preview) lets the model check its own work numerically instead of trusting a thumbnail.
- **Non-destructive by default.** Adjustments are adjustment layers, and destructive pixel operations run on an auto-created duplicate, so an edit stays reversible.
- **Built for modern Photoshop.** Editmamei targets Photoshop 2026 (v27.x) so it can rely on current, stable scripting descriptors rather than carrying a decade of drifted behavior.

## The MCP surface

- **Tools only.** The server declares the `tools` capability; there are no resources or prompts.
- **Self-describing.** The discovery chain is `ps_ping` (liveness and versions), then `ps_overview` (the working method: assess, plan, enact, check, iterate, plus a map of the tool groups), then `ps_list_capabilities`, a live map of what is registered in this session. GIMP has `gimp_ping` and `gimp_overview`.
- **Structured results.** Every tool declares an `outputSchema`, and successful calls return `structuredContent` alongside a short text summary. Tools that change what is active report the current document and layer back, so the model keeps an accurate picture of editor state between calls.
- **Images as content blocks.** Preview tools return downscaled JPEGs as MCP image content, which is how the model checks its own work. Setting `privacy.send_previews_to_llm` to `false` strips every image block from every result at the server boundary, nested results included.
- **Multi-step calls.** `ps_sequence` runs several steps in one call, with the option to roll them all back if one fails.
- **Only verified tools ship.** A new tool is registered at a `dev` tier and stays out of the tool list until it has passed live sessions against real Photoshop or GIMP ([`src/core/tool-tiers.ts`](../src/core/tool-tiers.ts)).
- **Listed in the [MCP Registry](https://registry.modelcontextprotocol.io)** as `io.github.editmamei/editmamei-photoshop-mcp` ([server.json](../server.json)).

**Tool counts and client caps.** Community registers 62 Photoshop tools (83 with Pro) and 29 GIMP tools, so a client can see up to 112. Some clients cap the list. If yours does, set `EDITMAMEI_EDITOR` to register one editor's tools only. The known caps are in [clients.md](clients.md#known-limits-across-clients).

**Long calls.** AI selection and large scene reads can take more than a minute. If your client's tool timeout is shorter, raise it. [clients.md](clients.md#known-limits-across-clients) lists the known defaults.

## Settings

Settings live in `~/.editmamei/settings.json`. Read and change them with `editmamei config`, then restart your client:

```bash
editmamei config list
editmamei config set telemetry.usage false
editmamei config set privacy.send_previews_to_llm false
editmamei config set editor photoshop
```

| Setting | Default | What it does |
| --- | --- | --- |
| `telemetry.usage` | `true` | Content-free usage events (see [Network requests](#network-requests)) |
| `telemetry.diagnostics` | `false` | Sanitized error detail, opt-in |
| `privacy.send_previews_to_llm` | `true` | `false` strips preview images from every tool result |
| `update_check` | `true` | Ask the npm registry for a newer version at startup |
| `editor` | `auto` | `photoshop` or `gimp` registers one editor's tools only |
| `gimp_path` | detected | Absolute path to the `gimp-console` binary (for Photoshop, use `PHOTOSHOP_PATH` below) |
| `automation.allow_execute_script` | `true` | Pro: `false` makes `ps_execute_script` and `ps_play_action` refuse |

## Environment variables

These are typically set in the client's `env` block:

| Variable | Purpose |
| --- | --- |
| `PHOTOSHOP_PATH` | Photoshop binary, when auto-detection can't find it (`editmamei install --photoshop-path` writes this for you) |
| `EDITMAMEI_GIMP_PATH` | The `gimp-console` binary, or `flatpak` to launch GIMP's Flatpak on Linux |
| `EDITMAMEI_EDITOR` | `photoshop` or `gimp`, as the `editor` setting |
| `EDITMAMEI_SCRIPT_TIMEOUT_MS` | Base script timeout in milliseconds (30000 is the default); every tool's budget scales with it, up to 10× |
| `EDITMAMEI_TELEMETRY_USAGE`, `EDITMAMEI_TELEMETRY_DIAGNOSTICS`, `EDITMAMEI_UPDATE_CHECK` | `true` or `false`, as the settings above, without writing the file |
| `EDITMAMEI_LICENSE_KEY` | Activates Pro at startup (how the Claude Desktop extension passes its license field) |
| `EDITMAMEI_SESSION_LOG_DIR` | Where per-session logs go (default `~/.editmamei/sessions/`) |

## Network requests

Core editing needs no network from this server: it talks to your editor through local processes. Photoshop's own Select Subject and Select Sky can use Adobe's cloud, depending on Photoshop's Image Processing preference; see the [FAQ](faq.md#does-it-need-generative-fill--adobe-cloud-features). The server makes these requests, and none of them carries image content or file paths:

- **Usage telemetry** (on by default, `telemetry.usage`) to Editmamei's own endpoint: tool name, success or error category, duration, response size, versions, OS and CPU architecture, install channel, which AI client connected and its capability flags, per-session counts and a random install ID. The network edge records country, time zone and serving datacenter on arrival.
- **Diagnostics** (off by default, `telemetry.diagnostics`) to the same endpoint: the failing tool and step, a sanitized error message and error-output tail, Photoshop's locale, and the open document's bit depth and color mode. Paths are reduced to file names, but an error message can still name a layer or repeat a value passed to a tool.
- **Update check** (on by default, `update_check`) to the public npm registry, with no identifiers.
- **Pro only:** activation (the license key and a hashed device ID) and a daily license check (the key) to the licensing service, a check for a newer Pro module, with the key, to Editmamei's delivery service at each start (it downloads the module if there is one), and a startup telemetry event reporting whether the module loaded.

The previews your client shows its model go to that model's provider, as any image in a chat would; `privacy.send_previews_to_llm=false` stops them. Every field, and your rights over the data, are documented in [privacy.md](privacy.md).

## Remote server: Editmamei Connect

For clients that can't launch local processes, [Editmamei Connect](https://editmamei.com/connect) is a separate, hosted remote MCP server at `https://connect.editmamei.com/mcp`: Streamable HTTP, OAuth 2.1 with PKCE, dynamic client registration and client ID metadata documents. Photos are uploaded to it and edited server-side, with no editor needed on the user's side. It is not part of this repository and has its own [terms](https://connect.editmamei.com/terms) and [privacy policy](https://connect.editmamei.com/privacy).
